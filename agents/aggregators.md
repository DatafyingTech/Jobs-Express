# Source: job aggregators and community boards

Aggregators are good for **finding** roles. They are not where you apply. The goal is always to end up on the employer's own application page (usually one of the company-board systems described in the company-boards guide) and apply there.

## Where to look

- **Himalayas** (himalayas.app/jobs): remote roles, filterable by category and pay. Open a job, then follow its "Apply" link to the employer.
- **Remote Rocket Ship** (remoterocketship.com): remote roles, sortable by newest. Follow through to the employer.
- **Hacker News "Who is hiring?"**: on the first weekday of each month the user `whoishiring` posts a thread. Find the latest one with WebSearch (`Ask HN: Who is hiring?` plus the current month), read the top-level comments, and pick the postings that fit. Many of them say "email us"; skip those, because you must never email anyone for the person. Use the ones that link to an application page.
- **Wellfound** (wellfound.com): startups. It often requires an account. If you are not already signed in, skip it and say so in your report; never create an account.

## How to work

1. Search by the person's titles and categories. Sort by newest when the site allows it.
2. Skim the listing. Apply the skip rules (exclusions, pay floor, location, hard requirements).
3. Run the duplicate check with the log helper.
4. Follow the link to the **employer's** application page. If it sends you to a third-party portal that makes you create an account, skip the role.
5. Apply following the shared rules and the company-boards guidance.

Do not apply through an aggregator's own "quick apply" or "one-click apply" buttons: those pass the person's details to a middleman.

Aggregator sites sometimes change layout or block automated browsing. If a site shows a CAPTCHA or a bot check, leave that site and tell the person in your final report.
